## Черновики карточек проектов

### Сервис прокси-доступа

Май 2026 · тестовое задание · fullstack

Задача: организовать регистрацию пользователей, выдачу доступа и отслеживание подключений.
Реализовано: авторизация, одноразовые ключи, REST API, личный кабинет, распределение виртуальных машин, отправка email через Celery, обновление статусов через WebSocket.
Стек: Python, FastAPI, SQLAlchemy, PostgreSQL, Celery, Redis, Vue.js, Docker.
Результат по резюме: автоматизирована выдача доступа и обновление статусов подключений.
Код: https://github.com/Miramisha/proxy-access-service

### Управление персоналом кейтеринга

Февраль 2026 · выпускная квалификационная работа

Задача: упростить набор сотрудников на мероприятия и подготовку документов.
Реализовано: Telegram-регистрация, мероприятия и смены, запись сотрудников, контроль заполненности, уведомления, инструменты менеджера, экспорт Word и Excel.
Стек: Python, Aiogram, MySQL, OpenPyXL, python-docx.
Результат по резюме: автоматизированы запись на смены и формирование документов.
Код: https://github.com/Miramisha/telegram-bot-catering-management

### Система обработки обращений

2024–2025 · backend-проект

Задача: централизовать учёт обращений пользователей.
Реализовано: создание обращений, смена статусов, фильтрация по датам, массовая отмена, хранение данных в MySQL.
Стек: Node.js, Express, MySQL, SQL.
Результат по резюме: автоматизирован учёт обращений.
Код: https://github.com/Miramisha/appeals-system

## Визуальное направление: инженерная точность и выразительная типографика

Светлый фон тёплого оттенка, почти чёрный текст, насыщенный синий акцент. Крупное имя, свободные поля, тонкие линии сетки и аккуратные подписи технологий. Один тёмный блок со схемой на первом экране придаёт странице контраст.

Предварительные токены:

- Фон: #F6F5F1; поверхности: #FFFFFF; основной текст: #171A20.
- Вторичный текст: #555D68; акцент: #2457E6; линии: #DADDE3.
- Шрифт: современный гротеск с кириллицей; кандидат Inter, окончательный выбор и лицензия проверяются на этапе дизайна. Моноширинный шрифт — только для технических подписей.
- Основной текст: 18 px desktop, 16 px mobile; подписи: не менее 14 px.
- Сетка: 12 колонок desktop, 4 mobile; контейнер до 1200 px; боковые поля от 20 px.
- Радиусы: 16–24 px для крупных поверхностей, умеренные для кнопок.

Контраст цветов проверяется в макете и реализации. Палитра — предложение, а не утверждённый дизайн.

## Анимация как демонстрация потенциала

Главный мотив — прохождение запроса через систему. Схема показывает абстрактное взаимодействие интерфейса, API и данных, а не заявляет устройство конкретного проекта.

| Элемент | Поведение | Ограничение |
| --- | --- | --- |
| Первый экран | Однократное появление текста с небольшим смещением, 450–650 мс | Текст доступен сразу; никакой обязательной заставки |
| Схема системы | Световой импульс проходит между тремя узлами за 1,5–2 с; запускается один раз | Повтор по кнопке; нет бесконечного отвлекающего цикла |
| Проекты | Появляются при входе в область просмотра, 300–450 мс | Контент остаётся виден без JavaScript |
| Карточка и ссылка | Подъём на 2–4 px, изменение рамки и движение стрелки, 160–220 мс | Равнозначное состояние фокуса; смысл не зависит от hover |
| Навигация | Переход к разделу с учётом высоты панели | Обычная прокрутка, без её перехвата |

На мобильных устройствах не использовать эффекты, зависящие от курсора. Учитывать prefers-reduced-motion: отключать перемещения и импульсы, сохранять весь контент. Основные анимации строить на transform и opacity. Не включать WebGL и тяжёлую 3D-сцену в первую версию.

## Простая архитектура

Целевая структура: одна страница, статический профессиональный контент, компоненты разделов и один небольшой модуль анимации. Данные проектов хранить отдельно от разметки в локальном файле. Не нужны база данных, CMS, личный кабинет и собственный backend: посетитель читает информацию и переходит по контактным ссылкам.

Для постоянной доступности достаточно публичного статического хостинга с HTTPS. Отдельный VPS потребуется только при появлении серверной функции. Окончательный стек, провайдер, условия публикации и подключение домена проверяются на соответствующих этапах; платные услуги сейчас не подключаются. Хостинг должен работать независимо от включённого компьютера владельца.
